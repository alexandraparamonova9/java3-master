# Лабораторная работа №3

Система управления студентами: Spring Boot 3.3.5, Java 17+, PostgreSQL,
EclipseLink/JPA, JWT (access + refresh). HTML/CSS/JavaScript раздаются самим Spring Boot.

## Конфигурация и запуск

Нужны JDK 17+, Maven и PostgreSQL. Maven можно запускать из IntelliJ IDEA.
Зависимости и плагины берутся из `pom.xml`.

1. Скопируйте `.env.example` в `.env`.
2. Задайте `DB_URL`, `DB_USERNAME`, `DB_PASSWORD`.
3. Выполните `openssl rand -base64 32` и вставьте результат в `JWT_SECRET`.
   Нужен обычный Base64 от случайного ключа минимум в 32 байта, а не произвольная
   строка. Пустое значение не подходит. Не публикуйте `.env` и сгенерированный ключ.
4. Подготовьте базу `students` в существующем PostgreSQL либо запустите сервис
   из имеющегося `docker-compose.yml`:

   ```sh
   docker compose up -d db
   ```

   Compose создаёт базу `students` на порту 5432, используя учётные данные из `.env`.
   Для него подходит `DB_URL=jdbc:postgresql://localhost:5432/students`.
   Данные сохраняются в именованном томе `students-data`.

5. Передайте четыре переменные окружения процессу Java. Spring Boot сам по себе
   не читает файл `.env`. В IntelliJ IDEA укажите переменные в Run Configuration.
   В macOS/Linux можно загрузить подготовленный файл в текущую оболочку:

   ```sh
   set -a
   . ./.env
   set +a
   mvn spring-boot:run
   ```

   Значения со специальными символами в `.env` для оболочки заключайте в одинарные
   кавычки. В Windows задайте те же переменные через IDE или PowerShell.

Откройте `http://localhost:8080/login.html` или `http://localhost:8080/`.
Также поддерживается предпросмотр JetBrains на `http://localhost:63342`
или `http://127.0.0.1:63342`: откройте `src/main/resources/static/login.html`
через IDE. CSS, JavaScript и переходы используют относительные пути, а запросы
API отправляются в Spring Boot на порту 8080. Бэкенд разрешает CORS только
для этих двух локальных адресов. **Предпросмотр IDE не запускает Java и базу:**
Spring Boot и PostgreSQL должны работать отдельно.
Открытие через `file://` и произвольные Live Server не поддерживается.

Таблицы создаёт EclipseLink. Саму базу PostgreSQL нужно подготовить до запуска.
Для поиска русских ФИО без учёта регистра нужна локаль БД с поддержкой кириллицы
(например, ICU `ru-RU`); локаль `C` не подходит для такого поиска.
Секрет JWT должен оставаться одинаковым между перезапусками, иначе старые токены
перестанут проходить проверку. Access действует 15 минут, refresh — 7 дней.

## Пользователи и роли

Регистрация всегда создаёт USER. Он может просматривать студентов.
ADMIN также может создавать, изменять и удалять записи. Сервер проверяет права
независимо от доступности кнопок в интерфейсе.

Для первоначальной подготовки администратора:

1. Зарегистрируйте отдельную учётную запись через страницу входа.
2. Подключитесь к своей базе от её владельца и назначьте роль именно этой записи:

   ```sql
   UPDATE users SET role = 'ADMIN' WHERE username = 'your_admin_username';
   ```

3. Перезапустите приложение и войдите заново, чтобы получить токены с новой ролью.
   Перезапуск нужен после ручного SQL-изменения: EclipseLink кеширует пользователей.

Публичного API назначения ADMIN нет. Пароль при регистрации хешируется BCrypt.
ИСУ ID студента после создания неизменяем как через PUT, так и через PATCH.
Существующий список автоматически загружает все страницы результатов поиска;
параметры серверной пагинации и сортировки доступны в REST API.

## Проверка

```sh
mvn test
mvn package
```

Автоматические тесты проверяют сервисы авторизации и студентов, JWT,
валидацию, HTTP-ошибки и ролевые ограничения. Для них не нужна работающая БД;
проверку EclipseLink/PostgreSQL следует выполнять отдельно на запущенном приложении.

Swagger: `http://localhost:8080/swagger-ui.html`.
OpenAPI: `http://localhost:8080/v3/api-docs`.

Импортируйте `postman/students-api.postman_collection.json` в Postman.
Укажите `baseUrl`, `adminUsername`, `adminPassword` подготовленного ADMIN.
Запускайте запросы по порядку: коллекция регистрирует отдельного USER, сохраняет
токены, проверяет вход/refresh/запрет изменения для USER, затем выполняет CRUD
тестового студента от ADMIN и удаляет только созданную ею запись.

Логи приложения: `logs/app.log`. При неверном пароле ожидается 401, занятом
логине/email — 409, ошибке полей — 400, недостаточных правах — 403.
